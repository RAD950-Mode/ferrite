# SOL950 on the RT-950 Pro

**Firmware feature design · proposed first release**

An operator opens SOL950, sees which stations are calling on a 10 m window, selects one to answer, and can follow the exchange until it appears in the log. The log remembers **who was worked, from where, and in which Maidenhead square** after the radio powers off. A worked-grid map and statistics page use the same saved contacts. The first release is an attended, single-radio experience. The [air-interface specification](sol950-design-v2.md), [bench measurements](sol950-lab-setup.md), and [cooperative reception proposal](sol950-cooperative-reception.md) cover the modem and subsequent experiments.

## Operating the radio

| View | What the operator sees and does |
| --- | --- |
| **Operate** | Header shows the full local identity, four-character grid and source, USB dial, and UTC slot readiness. The activity list shows full peer call, grid when known, SNR, and age. Turn the knob to select a caller. OK opens **Answer**; **Call CQ** starts an attended calling session. Entering the screen starts listening. |
| **Active contact** | Keep the peer identity visible. Show the next action in ordinary language, e.g. “Report received · replying in 6 s” or “Final report sent · listening for retry.” Show **Stop** throughout. Render **Saved** only after storage acknowledges the contact. A stop cancels queued transmissions and requests normal unkey for an active TX. |
| **Log** | Newest first. A detail page shows UTC, both full calls and grids, window, sent/received SNR and availability of either grid. A completed repeat contact gets its own row after cooldown. |
| **Worked grids** | Open the map, select a grid to see its contact count and most recent contact, then open the matching log rows. A sortable list by grid or most recently worked supplies the same lookup on the keypad. |
| **Stats** | Show completed QSOs, unique peer identities, distinct worked GRID4s, and QSOs missing a peer grid. Offer **All saved contacts** and **Today (UTC)**. Full calls and dates remain readable on detail pages. |
| **Setup** | Edit base call, operating prefix, numeric suffix, grid source/value, USB window and signed RX correction in Hz. Show the resulting on-air identity and grid before saving. |

Open in Monitor even if a previous session ended during TX. A timing indicator distinguishes acquiring UTC, ready, and holdover expired. A manual grid supplies location only. Timing uncertainty, radio band/power checks, Dry TX, relay limits, aborts, and clean unkey all continue through their existing owners. On mode exit or local PTT takeover, cancel outstanding automatic replies and restore the prior radio configuration. Preserve completed log records. ## Station identity

Represent an identity as three fields. The **base call** initially comes from Ferrite’s radio callsign setting and uses the existing standard callsign validator. Leave an unset or unsupported base visible for correction. The **operating prefix** defaults to None and accepts an uppercase alphanumeric designation such as KP2; propose one to four characters for this wire revision. The **station suffix** defaults to None; propose **1–15** in the first release for straightforward keypad selection and four-bit encoding. Zero is the internal absent value. An edit to this SOL950 profile does not edit the shared callsign or APRS SSID. Preview the full string, including separators only when present. [Radio settings](../crates/ferrite-app/src/settings.rs) · [Current callsign codec](../digimodes/usol950/src/frame.rs)

| Base | Prefix | Suffix | On air, in the list, and in the log |
| --- | --- | --- | --- |
| NQ6N | None | None | NQ6N |
| NQ6N | None | 2 | NQ6N-2 |
| NQ6N | KP2 | None | KP2/NQ6N |
| NQ6N | KP2 | 1 | KP2/NQ6N-1 |

Use the full tuple for addressing, session lookup, cooldown, recent-grid association and unique-station statistics. In particular, an ACK to NQ6N-2 cannot complete a contact for NQ6N-1. Allocate space for up to 14 display characters (four-character prefix, slash, six-character base, hyphen and two digits). Show a full-width identity in confirmation and log detail. Freeze the local identity and grid for a contact; apply setup changes to the next contact. Prefix entry is operator-supplied. A typed prefix alone supplies no peer location.

### On-air compatibility and an implementable extension

The current 64-bit CQ and report formats carry **28-bit standard calls**. A UI-only suffix would silently address the wrong radio. Preserve existing frames and the three-slot fast path for plain calls. For a contact involving a decorated call, both endpoints need an extension carrying the complete sender and recipient. This is a proposed addition to the air specification; freeze vectors and demonstrate interoperability before enabling decorated TX. Plain-call operation can enter bench testing independently.

One lossless prototype uses the unused sender-code range. Reserve a marker of six one-bits at payload bits 62–57; this places the legacy sender at or above `0x0FC00000`, beyond `Callsign::MAX_RAW`. Current decoders reject this range. For extension frames concatenate bit 63 and bits 56–0 to obtain 58 usable bits. Allocate two to fragment index, 24 to a message checksum/tag, and 32 to fragment data. Retain the physical frame CRC and LDPC. [Frame packing and rejection](../digimodes/usol950/src/frame.rs)

- Encode an exact station identity in 53 bits: 28-bit base, 21-bit prefix (four base-37 positions with trailing blank padding; all blank means absent), and four-bit suffix. A two-bit logical type selects CQ, initial report, or confirmed report; reserve the fourth value. CQ contains the sender, GRID4 and power (74 bits, three fragments). Each directed report contains sender, recipient, sender GRID4 and SNR (128 bits, four fragments). The report type carries the ACK state. Use the existing unknown-grid sentinel. Zero-pad the final CQ fragment.
- Transmit consecutive indices in successive eligible TX slots on the same window and subchannel. Start a group at index zero. Bind its tag to the full logical payload, window and initial UTC slot. Specify bit order, prefix alphabet, checksum parameters and slot encoding in the wire amendment. Reassemble bounded groups per window, subchannel, initial slot and tag; reject conflicting indices, wrong tag or stale/incomplete groups. Only a fully validated message supplies identity, grid or QSO evidence. On retry, begin a new group. The checksum detects accidental mixes; it does not authenticate stations.
- A plain-call CQ may advertise extension capability in a reserved CQ bit. A decorated pouncer answers a capable plain caller using extended reports. Plain stations answering a decorated CQ also send extended reports. Retain reception of ordinary traffic on every upgraded radio. Label an undecorated caller with unknown extension support when a decorated local identity is selected. Never substitute the base call to make an exchange succeed.
- This conservative format spends airtime to preserve exact identities. A decorated CQ followed by two directed reports uses **11 bursts** even before retries; the 3-TX-per-minute limit still applies per station. Show fragment progress, reserve eligible slots for the outstanding group, and start the peer response timer after its last fragment. Use the existing five-minute session limit with explicit expiry if retries run out of time. Measure completion time under a single erased fragment. A shorter encoding can replace this prototype before the wire format freezes if weak-opening tests show the cost is too high.

## Grid selection and credit

**Manual** accepts four or six Maidenhead characters in either case, validates them using Ferrite’s existing grid parser, and shows the uppercase GRID4 that will go on air. Preserve the manual value across reboots and switches to GPS. **GPS** uses a recent valid onboard position, converts it using Ferrite’s exported six-character `grid(Pos)`, and takes the first four characters. Show the resolved grid, source and fix age. With no recent fix, show **GPS waiting · grid unknown** and use the protocol sentinel if the operator calls with valid UTC. Default a new profile to GPS. Only transmit GRID4; a six-character manual entry or precise GPS fix stays local. [Grid helpers](../crates/ferrite-app/src/lib.rs) · [GPS data and fix freshness](../crates/ferrite-app/src/gpsdata.rs) · [Wire grid codec](../digimodes/usol950/src/frame.rs)

SOL950 must request GPS time while armed and position when GPS grid is selected. Keep position freshness distinct from UTC holdover. Use the onboard-fix accessor explicitly: the general `position()` may return a configured fixed position. Test +180° longitude wrap and the northern latitude endpoint before converting to a grid; neither endpoint may produce an invalid field letter. Update the operating display when a moving station enters a new grid and retain the snapshot from the active exchange in its log row.

A **worked grid** is a known *peer* GRID4 attached to a locally completed QSO. Hearing a CQ adds activity only. In a plain three-slot exchange, the silent pouncer sends a report without a grid; the CQ caller can legitimately finish with the peer grid unknown. Associate a CQ only by the exact identity, same window and current session. Preserve unknown explicitly when there is no such evidence. To exchange both grids with plain frames, allow the operator to send a CQ before answering; upgraded extended reports carry the reporter’s grid directly. Never infer a grid from a prefix, an unrelated historical QSO, or the local grid.

## Durable log, stats and map

The current engine keeps 16 recent records in RAM. Add a dedicated versioned SOL950 journal in external flash using Ferrite’s store task and existing CRC/commit conventions. A candidate allocation is part of the 128 KiB `layout::FREE` region; reserve it through the layout, restore and writable-region contracts before use. Size it from the encoded record and sector overhead. Show the resulting capacity. When full, keep existing contacts, indicate **Log full**, and require the operator to manage space before arming another logged session. [Engine records](../crates/ferrite-core/src/sol950.rs) · [Flash layout](../crates/ferrite-core/src/layout.rs) · [Persistent log patterns](../crates/ferrite-store/src/logs.rs)

Each completion records a stable contact key (local and peer identities, window and session start UTC slot), completion UTC, both grid snapshots, local grid source, sent and received SNRs as actually exchanged, and format version. Persist the completion once even if the final report is repeated. Retry a failed write with the same key, expose an unsaved completion in the UI, and count it in saved statistics only after commit. On restart discard torn records and rebuild indexes from valid entries. Retain recent completed session keys through their cooldown so reboot and replay cannot create another entry. Scope all-time statistics to the saved journal and count each distinct four-character peer grid once across identities and local grid changes.

For the first **map**, render a worldwide Maidenhead overview with an 18 × 18 field lattice, north up and longitude increasing east. Highlight fields containing worked squares. Select a field to open its **10 × 10** square view; for field FN, column 3 and row 1 from the south is **FN31**. Distinguish current local square, worked squares, and selected cursor by outlines or fills readable without color. Selecting a square shows its full locator, QSO count and last worked time. Mark a square only at GRID4 precision. Unknown-grid QSOs still count in totals. The map works offline without geographic tiles, a current GPS fix, or a large bitmap. Build the overview from saved records outside the DSP task; cache field totals and load just the selected field’s 100 cell counts. Never rescan SPI flash on every paint or borrow live decoder workspace.

## Integration and acceptance

1. **Vertical slice on two radios.** Add an Operate screen and explicit attended CQ/Answer commands, integrate the streaming receiver and bounded decoded-frame delivery, and route timing, 28 MHz SI USB selection, AVC-on receive, RX correction and BK4829 PLL TX through their existing tasks. Trace slot, timing uncertainty, actual RF readiness, TX completion and log acknowledgment. Verify per-block DSP deadlines, peak stack/RAM and final-sample-to-reply latency under multiple candidates. A deliberately missed deadline skips the transmission and leaves an observable pending reply. [Radio task](../firmware/src/tasks/radio/) · [DSP task](../firmware/src/tasks/dsp.rs) · [Bench baseline](sol950-lab-setup.md)
2. **Make a plain-call QSO using the actual controls.** Two independently timed radios must each save one contact. Erase the final ACK, repeat it during linger, abort an armed report, and restart after a completed write. Verify log counts and both screens. Check a no-fix GPS start, manual entry, GPS acquisition, and a grid change during a contact.
3. **Exercise identity interoperability.** Publish encoded vectors and simulate every example above as both caller and responder. Run NQ6N-1 and NQ6N-2 on the same window; exactly the addressed peer may reply or log. Test old-decoder rejection, loss of each fragment index, interleaved callers, mixed tags, duplicates, cancellation, and expiry. Then repeat a KP2/NQ6N-1 contact on hardware and verify the full identities and both grids on both radios.
4. **Verify the worked-grid experience.** Seed logs with repeated FN31 contacts, a new grid, an unknown-grid contact, and the same base with distinct suffixes. Compare Stats, map cells and filtered log rows before and after reboot, a failed write and a full journal. Verify that crossing UTC midnight changes Today without changing all-time totals. Run the simulator screen checks and the two-radio test before declaring the feature ready for attended field QSOs.

Track field success as the fraction of attempts producing exactly one matching record at each end within 60 seconds for the plain-call exchange. Report decorated contacts separately with elapsed time, identity format, retries and completion rate; their longer wire exchange needs its own baseline. Receiver sensitivity improvements and cooperative reception can use the same interface and journal after the basic contact and logging experience is working.
